# Матрица основной ветки развития

> **Статус:** внедренческая карта 63 узлов после расширения реестра ночным выпасом,
> стенгазетой, телефоном, радио и зимней работой клуба.
> Триггеры и условия ниже сокращены для сверки; источником механики остаются
> [реестр квестов](../../../manual/design/chairman/quests.md#7-базовые-квесты) и
> `design.db`. Строки игрока лежат отдельно в [Эпохе I](../texts/development-quests-era-i.md)
> и [Эпохах II–III](../texts/development-quests-later-eras.md).

## Как читать

| Поле | Значение |
|---|---|
| **Линия** | `Ствол`, `Производство`, `Управление`, `Село и люди` |
| **Статус** | `Основной` — общий корпус; `Условный` — может не появиться по состоянию мира; `Необязательный` — отдельная выбранная ступень линии |
| **Смысловая опора** | Более ранний узел той же темы для чтения ветки. Это не исполнимая ссылка «квест → квест»: открытие и закрытие определяют факты мира в `quest.opens_fact` и `quest.closes_fact` базы дизайна |
| **Подача: готово** | Сцена или точная заготовка уже написана в RPG-мануале |
| **Подача: нужна** | Место для следующего текстового прохода; новая механика не предполагается |
| **Мир / событие** | Причина уже читается поведением жителей, видом юнита, письмом, алармом или игровым событием; отдельная сцена не нужна |

Все квесты можно убрать из тетради, ни один не блокирует механику. Необязательность в
матрице означает положение внутри ветки, а не отдельное правило отказа
([правила квестов](../../../manual/design/chairman/quests.md#3-правила)).

## Последовательности, которые выстраивает мир

Стрелка ниже показывает смысловое продолжение темы, но не связь между записями тетради.
Каждый следующий квест приходит по собственному факту мира: изба сначала построена, затем
работает; работающая изба позволяет выпустить стенгазету. Эти состояния стоят рядом во
времени, но не подменяют друг друга.

```text
«Своя контора» → «Счетовод»
«Учить детей» → «Учитель»
«Разметить сеть» → «Пустить ток»
«Куда пойти вечером» → «Стенгазета»
                    └→ «Клуб» → «Зимние вечера» → «Дом культуры»
                                       └────────────→ «Телевизор в клуб» [событие «Телевидение»]
«Своя станция» ┬→ «Где ставить машины»
               └→ «Свой трактор»
«Провод до конторы» → «Кому первому»
«Радиоузел в клубе» → «Чтоб слышно было»
«Спортплощадка» → «Большой футбол»
«Фельдшер в селе» → «Своя больница»
«Счетовод» → «По науке» → «Дать полномочия» → «Право на ошибку» → «Без председателя»
```

Исполнимые пары заполняются в `quest.opens_fact` и `quest.closes_fact` базы дизайна по мере
прохода веток. RPG называет владельцу базы существующий факт либо точное машинное условие,
если факта ещё нет; собственного порядка и счётчика не заводит.

## Общие проверки поведения

| Случай | Ожидаемое правило | Статус опоры |
|---|---|---|
| Одновременно открылись несколько обычных квестов | В тетради не больше трёх, остальные ждут | Принято в правилах очереди |
| Переход эпохи открыл пакет | Эпохальные выдаются по одному | Принято в правилах очереди |
| Игрок отказался от необязательного узла | Продолжение ветки не рвётся, чужие награды не теряются | Принято в правилах веток |
| Игрок отказался от любого квеста | Запись больше не показывается, механика не закрывается, награда теряется | Принято в общих правилах |
| Аларм и квест совпали по теме | Аларм показывается, квест скрыт; очки начисляются только один раз | Принято в стыке с алармами |
| Квест выполнил автономный специалист | Закрывается по состоянию хозяйства, очки получает председатель | Принято в стыке с делегированием |
| Условие закрытия выполнено **до фактической выдачи из очереди** | Квест не показывается; запись ставится закрытой, её последствия открываются, награда выдаётся обычным способом без карточки выполненного квеста | **Принято `boss`: просьба о сделанном уже не является просьбой** |
| Игрок отказался от `quest_e1_25`, который служит воротами ночного выпаса | Запись исчезает, а предложение возвращается следующим летом, пока условия держатся | **Принято `boss`: неотказываемых квестов нет; отказ снимает запись, а не возможность** |
| Игрок отказался от `quest_e3_08`, который служит воротами семейных телевизоров | Запись и очко снимаются; возможность остаётся, предложение возвращается в следующий подходящий клубный вечер | **Принято `boss`: неотказываемых квестов нет, «всем селом» не равно 100% жителей** |
| Система не производит и не хранит отправку тяжёлого больного в район | `quest_e3_05` открывается в III эпохе при работающем ФАПе с фельдшером; сцена говорит только о порядке мира, не о случившемся в партии | **Принято `boss` после проверки `core`; нового следа и возраста юнита не заводится** |
| Событие «Радиофикация» требует клуба с уже построенным радиоузлом | Радиоузел не входит в условие: событие ждёт электрификацию и построенный электрифицированный клуб | **Круг снят `boss` в базе дизайна и каноне** |
| Открывается `quest_e2_29` «Зимние вечера» | Первая зима Эпохи II при работающем клубе; «пустота» и порог охвата не считаются | **Принято `boss`; закрывает первый фактически завершённый зимний цикл занятий клуба** |
| Специалист сквозной ветки уехал до ошибки | Ветка ждёт следующего человека, получившего автономию в выбранной области | Принято содержанием RPG; требуется сверка хранения состояния |
| После ошибки автономию сохранили | Финальный узел ждёт своих условий | Принято содержанием ветки |
| После ошибки уровень снизили или отобрали | Финальный узел ждёт нового достижения автономии; дополнительной награды нет | Принято содержанием ветки |

## Следующий проход по матрице

1. Проходить ветки по одной и передавать владельцу базы пары «квест → существующий факт» либо
   точное машинное условие для нового факта.
2. После заполнения `opens_fact` и `closes_fact` сверять смысловые последовательности с миром,
   не превращая их в связи «квест → квест».
3. Проверить, что переданные строки и адреса сцен дошли до баз владельцев.
4. После импорта пройти реальный порядок выдачи и исключить две постановочные сцены
   подряд.
